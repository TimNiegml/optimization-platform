# 耦合优化平台 · 演示视频导演稿

> 用途：拍一条把**商业优势**和**技术优势**同时讲透的平台演示片。
> 读者：导演 / 出镜人 / 录屏操作者 / 剪辑。
> 原则：**每一句口播，都要有一个屏幕上的东西作证**。稿子里每个镜头都标了「证据」一栏——
> 那就是这句话对应的画面。没有证据的话，不说。

---

## 0. 一条主线，四块内容

**主线（贯穿全片的一句话）：**

> **把耦合调试，从"专家的手艺"，变成"可复制、可验收、可复用的工程资产"。**

四块内容 = 回答客户心里的四个问题：

| 块 | 客户心里的问题 | 我们的回答 | 对应 Act |
|---|---|---|---|
| 一 | 没有真机就没法搞算法？ | **Zemax 仿真、设备仿真、真机，同一个接口，同一套算法方案** | Act 1 |
| 二 | 换个产品是不是要重来一遍？ | **换产品只换三样东西，流程和算法资产全部复用** | Act 2 |
| 三 | 算法参数还是要专家调？怎么知道它在产线上稳？ | **Agent 自动寻优 + 数字孪生多场景打分，选出最稳最快的方案** | Act 3 |
| 四 | 我的仪器接得进来吗？ | **三个方法就接进来：六足、干涉仪、功率计、SFR** | Act 4 |

**贯穿的技术主张（每一幕都要落一次）：**
Agent 有手、有眼，**但没有裁判权**——分数永远是平台确定性算出来的。

## 1. 成片规格

| 版本 | 时长 | 用途 | 怎么来 |
|---|---|---|---|
| **A 主片** | ~10:00 | 客户技术决策层、内部评审、方案汇报 | 按本稿完整拍 |
| **B 精简片** | 90" | 展会循环播放、微信转发、销售开场 | 从主片抽帧重剪，分镜见 §6 |
| **C 分段短片** | 4 段 × 1.5–2' | 销售按客户关心点单发 | 主片按 Act 切开，各加 5" 片头片尾 |

**录制参数**

- 1920×1080 / 60fps（画布有拖拽和实时曲线，30fps 会拖影）。
- 浏览器缩放 110%，画布右上「字号」滑块拉到 **16**；用**浅色主题**（投影和微信压缩后更清楚）。
- 终端字号放大到 18pt 以上，配色用高对比；**不要**用透明背景终端。
- 录屏工具关掉鼠标高亮特效，但**开启点击涟漪**——观众要看清你点了哪。
- 口播单轨录，剪辑时对画面；**不要边操作边即兴讲**，节奏会散。

### Act 1 · 双仿真：Zemax 仿真 与 设备仿真 `1:20–3:05`

> **本幕要让客户信的一件事**：不用等真机，算法方案就能做完、验完。

**【1-1 / 1:20 / 15"】**
- **画面**：一张对照图：左「Zemax 光学仿真」右「设备/台架仿真」，中间一个大大的等号，等号下写 `y = f(x)`。
- **口播**：「先说仿真。对平台来讲，Zemax 里的一次光路计算，和台架上的一次真实测量，是同一件事——**给一组自变量，返回一组因变量**。」
- **花字**：`y₁,y₂,… = f(x₁,x₂,…)`

**【1-2 / 1:35 / 40"】** ← **本幕主镜头**
- **画面**：布局 1，画布。
- **操作**（提前排练，一气呵成）：
  1. 「仿真场景」下拉，选 `多峰`；
  2. 点「载入示例」，流程自动铺开：`grid_scan 找光` → `nelder_mead 精调` → `parametric_fit 均衡`；
  3. 点 **▶ 运行**；
  4. 轨迹图出现，切「收敛」视图，指一下下方的**算子色带**；
  5. 切「2D」视图，勾上**响应面等高线**。
- **口播**：「这是一个设备仿真的场景。找光、精调、均衡，三段流程拖出来，直接跑。收敛曲线下面这条色带，标的是每一段是哪个算子在干活——**哪一步花了时间、哪一步真的有增益，一眼看得见**。切到二维视图，叠上响应面，就能看清算法是怎么在这个地形上爬到峰顶的。」
- **花字**：`算子色带 = 每一段的成本与增益` / `响应面等高线`
- **证据**：真实运行，不是录好的视频。

**【1-3 / 2:15 / 35"】**
- **画面**：布局 2。左边编辑器打开 `examples/device_template.py`，高亮三个方法。
- **口播**：「那 Zemax 怎么接？平台对'一个被优化的东西'只有三个要求：**轴能动、轴能读、测量能读**。`move`、`get`、`get`。把这三个方法里的内容换成 ZOS-API 调用，Zemax 就是平台眼里的一台设备——自变量是装配自由度，因变量是 MTF、SFR、像面倾斜。**算法方案一行不用改。**」
- **花字**：`Axis.move() / Axis.get() / Meter.get()` → `三个方法，接进任何东西`
- **证据**：`optplat/userdev.py`、`examples/device_real_hardware.py`。
- ⚠️ **话术边界**：说「按同一个契约接入」，**不要说「已内置 Zemax 连接器」**。见 §7。

**【1-4 / 2:50 / 15"】**
- **画面**：一张三格图：`Zemax 仿真` → `设备仿真` → `真机`，三格下面同一条流程图。
- **口播**：「于是同一套算法方案，先在 Zemax 里做，再在设备仿真里验，最后原样搬到真机上。**占机调试的时间，被挪到了上机之前。**」
- **花字**：`占机时间 → 挪到上机之前`（这是本幕的**商业价值落点**）

### Act 2 · 一个平台，适配差异巨大的产品 `3:05–4:40`

> **本幕要让客户信的一件事**：产品差异再大，平台不用重写；产品演进时，方案是能继承的资产。

**【2-1 / 3:05 / 20"】**
- **画面**：三列对比表格，逐列点亮。
- **口播**：「产品和产品之间的差异有多大？自由度可能是三轴，也可能是六轴；指标可能是耦合功率，也可能是 PDL、中心波长、SFR；判据可能是最大化，也可能是打到一个目标值，或者按范围扫一条特性曲线。」
- **花字**：三列 → `自变量：3轴 / 6轴 / 更多` `因变量：功率 / PDL / 波长 / SFR` `目标：最大·最小·定值·扫描`
- **证据**：`optplat/vocs.py` 的四种目标模式。

**【2-2 / 3:25 / 35"】** ← **本幕主镜头**
- **画面**：布局 1，画布。
- **操作**：
  1. 打开一个节点的配置面板，把「目标方式」从`最大`切到`逼近目标值`，填一个目标值；
  2. 打开「变量」勾选，加/减一个自变量——**面板里的每轴参数表格实时多出/少掉一列**；
  3. 打开通道表，指一下`测量组`列和右边的**测量总时长**预估。
- **口播**：「但是对平台来说，变的只有三样：**几个自变量、几个因变量、目标是什么**。这三样是声明出来的，不是写死在代码里的。目标从最大化改成打定值，点一下。加一个自由度，算法的每轴参数表自己就多出一列。**没有一行代码要改。**」
- **花字**：`变的只有：变量 · 目标 · 设备` / `不变的：流程 · 算法 · 引擎 · 护栏`

**【2-3 / 4:00 / 25"】**
- **画面**：点开「📁 方案库」，展示预存的多个产品方案；随便加载一个，流程立刻铺满画布。
- **口播**：「更值钱的是这个——**方案库**。每一个调好的流程都是一份 JSON，存下来就是资产。产品演进的时候，上一代的耦合方案直接加载出来，改掉变化的那部分，剩下的全部继承。**这就是为什么产品迭代的算法周期能被大幅压缩：你不是从零开始，你是从上一代开始。**」
- **花字**：`方案 = JSON = 可继承的资产`
- **证据**：`optplat/solutions.py` + `solutions/` 文件库，与画布保存/加载互通。

**【2-4 / 4:25 / 15"】**
- **画面**：一张简单的时间轴对比条：`传统：数周—数月` vs `平台：数天`（下面小字注明"取决于产品复杂度"）。
- **口播**：「新产品从零起，是配置加自动寻优，不是重新开发；演进产品，是在已有方案上改。」
- **花字**：`新产品：开发 → 配置` / `演进产品：继承 → 微调`
- ⚠️ **话术边界**：时间数字请填**你们自己实测过的**项目周期。见 §7。

### Act 3 · 专用算法 + 通用算法 + Agent 寻优 + 数字孪生打分 `4:40–8:00`

> **全片最重的一幕。** 这一幕讲完，技术优势和商业优势都要落地。

**【3-1 / 4:40 / 25"】**
- **画面**：算法库列表铺开（画布左栏算法节点，11 个），分两组高亮。
- **口播**：「平台里有两类算法。一类是**产品专用**的——阻尼灵敏度求解、公式法、非标拟合，这些是把光学工程师脑子里的先验知识写进去的，知道峰是什么形状，就直接解，不用瞎搜。另一类是**AI 通用**的——贝叶斯优化、单纯形、梯度上升，不需要先验，靠采样自己找。」
- **花字**：`专用算法：把先验写进去` / `通用算法：不需要先验`
- **证据**：`optplat/registry.py` 的 11 个算法及其 `category`。

**【3-2 / 5:05 / 30"】** ← **Agent 概念的正式定义，慢一点讲**
- **画面**：三层动画依次点亮。
- **口播**：「这两类算法怎么组合、参数怎么定？交给 Agent。我们说的 Agent 是三层实实在在的东西，不是一个说法。**第一层，自动调优器**：在'粗调 × 精调 × 拟合'的组合空间里，自己生成候选方案、自己跑、自己排名。**第二层，MCP 工具层**：平台的二十个能力，全部开放给 Agent 调用——建流程、加节点、跑、诊断、审计。**第三层，共享工作区**：Agent 改了流程，你面前的画布实时刷新；你在画布上给它发指令，它下一轮就读到。**人和 Agent 是同屏工作的。**」
- **花字**：`L1 自动调优器` / `L2 二十个 MCP 工具` / `L3 人机同屏工作区`
- **证据**：`optplat/autotune.py`、`optplat/mcp_server.py`（20 个 `@mcp.tool`）、`optplat/workspace.py`。

**【3-3 / 5:35 / 45"】** ← **本幕主镜头之一**
- **画面**：布局 1，点开「🤖 自动调优」面板。
- **操作**：
  1. 三个权重滑块：质量 / 时长 / 稳定性——**边讲边拖动其中一个**，让观众看到这是可调的取舍；
  2. 点运行；
  3. 结果出来：候选卡片列表 + **帕累托散点图**；
  4. 鼠标点一下帕累托前沿上的绿点，再点「采用」，流程自动替换到画布上。
- **口播**：「看这里。我告诉它，我要的是**质量、时间、稳定性**这三者的什么样的平衡——滑块就是你的取舍。然后它自己生成十二套候选方案，全部跑一遍。最好的一套：**质量 0.997，稳定性 100%，仿真耗时 101 秒**。最差的一套：质量 0.27，一次都没达标。**这两套方案的差别，全在参数上——这就是原来专家要试一个星期的东西。**帕累托前沿上的这些点，是没法互相碾压的方案，你按你的产线节拍挑一个，一键采用。」
- **花字**：`12 套候选 / 4 秒跑完` `最优 0.997 · 100% 稳定 · 101s` `最差 0.27 · 0% 稳定`
- **证据**：§9 复现表第 2 条，现场跑。

**【3-4 / 6:20 / 35"】**
- **画面**：一张流程动画：`真机采集的数据点云` → `建模` → `虚拟场景（可复制成 N 份）`；每份场景标注不同的偏差来源。
- **口播**：「但是仿真场景是我们造的，客户的产品不是。所以平台开了一个口子：**你自己采的数据，可以直接变成一个虚拟场景**。把采到的 x-y 数据喂进去，平台建出一个响应面，这就是你这个产品的**数字孪生**。然后关键的一步——把它**复制成很多份**，每一份改掉一点：上料位置偏一点、机台零位差一点、噪声大一点。**这些就是你产线上真实会遇到的差异。**」
- **花字**：`客户数据 → 数字孪生` / `一个孪生 → N 个带偏差的场景`
- **证据**：`optplat/models.py` 的 `dataset_idw` provider（可插拔，未来可换 GP/RBF）。
- ⚠️ **拍摄注意**：孪生的保真度**强依赖采样密度**。见 §8-③，不要用稀疏均匀采样去拍这一镜。

**【3-5 / 6:55 / 50"】** ← **全片最强的一镜。这里有一个反转，一定要留出停顿。**
- **画面**：布局 3，终端。跑 §9 复现表第 3 条命令，输出三行排名。
- **口播**：
  「现在，把刚才自动调优选出来的方案，扔进多场景打分。
  平台有两套题：一套是**可见的**，调参的时候随便用；另一套是**冻结的**——七个场景，不同的起点、不同的地形、不同的噪声，**调参的人和 Agent 都碰不到它**。
  （**停顿 1 秒**）
  看结果。刚才自动调优排第一的那套方案，**在冻结场景上不及格**——达标率只有 57%，跟可见场景的差距 0.158。它不是更好，它只是**更适应我们让它看过的题**。
  真正通过验收的，是排在第二的贝叶斯方案：**达标率 86%，质量 0.965**，稳稳地过。
  这个差距，平台叫它**泛化间隙**。**如果没有这一步，你会把那套在实验室里最漂亮、在产线上最不稳的方案，交到产线上去。**」

## 4. 口播连读稿（配音用）

> 把下面这段直接给配音，分镜时码见 §3。段落间的 `//` 是换镜停顿点。

一条光器件产线上，最难自动化的一步，是耦合。//
难在三件事。第一，算法要跟着产品走——换一个产品，扫描策略、拟合模型、约束条件，全部重来。第二，调参靠专家，专家的经验留在他脑子里，留不下来。第三，你没法提前知道，实验室里调好的算法，上了产线还稳不稳。//

我们做的这个平台，核心只有一句话：优化流程本身，是一份声明式的数据。画布上拖出来的、API 传进来的、Agent 写出来的，最后都是同一份 IR，跑在同一个执行核上。// 所以，界面只是 IR 的编辑器，Agent 也只是 IR 的编辑器。这一点决定了后面所有的能力，都能互相组合。//

先说仿真。对平台来讲，Zemax 里的一次光路计算，和台架上的一次真实测量，是同一件事——给一组自变量，返回一组因变量。// 这是一个设备仿真的场景。找光、精调、均衡，三段流程拖出来，直接跑。收敛曲线下面这条色带，标的是每一段是哪个算子在干活——哪一步花了时间、哪一步真的有增益，一眼看得见。切到二维视图，叠上响应面，就能看清算法是怎么在这个地形上爬到峰顶的。// 那 Zemax 怎么接？平台对"一个被优化的东西"只有三个要求：轴能动、轴能读、测量能读。把这三个方法里的内容换成 ZOS-API 调用，Zemax 就是平台眼里的一台设备——自变量是装配自由度，因变量是 MTF、SFR、像面倾斜。算法方案一行不用改。// 于是同一套算法方案，先在 Zemax 里做，再在设备仿真里验，最后原样搬到真机上。占机调试的时间，被挪到了上机之前。//

产品和产品之间的差异有多大？自由度可能是三轴，也可能是六轴；指标可能是耦合功率，也可能是 PDL、中心波长、SFR；判据可能是最大化，也可能是打到一个目标值，或者按范围扫一条特性曲线。// 但是对平台来说，变的只有三样：几个自变量、几个因变量、目标是什么。这三样是声明出来的，不是写死在代码里的。目标从最大化改成打定值，点一下。加一个自由度，算法的每轴参数表自己就多出一列。没有一行代码要改。// 更值钱的是这个——方案库。每一个调好的流程都是一份 JSON，存下来就是资产。产品演进的时候，上一代的耦合方案直接加载出来，改掉变化的那部分，剩下的全部继承。这就是为什么产品迭代的算法周期能被大幅压缩：你不是从零开始，你是从上一代开始。// 新产品从零起，是配置加自动寻优，不是重新开发；演进产品，是在已有方案上改。//

平台里有两类算法。一类是产品专用的——阻尼灵敏度求解、公式法、非标拟合，这些是把光学工程师脑子里的先验知识写进去的，知道峰是什么形状，就直接解，不用瞎搜。另一类是 AI 通用的——贝叶斯优化、单纯形、梯度上升，不需要先验，靠采样自己找。//

这两类算法怎么组合、参数怎么定？交给 Agent。我们说的 Agent 是三层实实在在的东西，不是一个说法。第一层，自动调优器：在"粗调 × 精调 × 拟合"的组合空间里，自己生成候选方案、自己跑、自己排名。第二层，MCP 工具层：平台的二十个能力，全部开放给 Agent 调用——建流程、加节点、跑、诊断、审计。第三层，共享工作区：Agent 改了流程，你面前的画布实时刷新；你在画布上给它发指令，它下一轮就读到。人和 Agent 是同屏工作的。//

看这里。我告诉它，我要的是质量、时间、稳定性这三者的什么样的平衡——滑块就是你的取舍。然后它自己生成十二套候选方案，全部跑一遍。最好的一套：质量 0.997，稳定性 100%，仿真耗时 101 秒。最差的一套：质量 0.27，一次都没达标。这两套方案的差别，全在参数上——这就是原来专家要试一个星期的东西。帕累托前沿上的这些点，是没法互相碾压的方案，你按你的产线节拍挑一个，一键采用。//

但是仿真场景是我们造的，客户的产品不是。所以平台开了一个口子：你自己采的数据，可以直接变成一个虚拟场景。把采到的 x-y 数据喂进去，平台建出一个响应面，这就是你这个产品的数字孪生。然后关键的一步——把它复制成很多份，每一份改掉一点：上料位置偏一点、机台零位差一点、噪声大一点。这些就是你产线上真实会遇到的差异。//

现在，把刚才自动调优选出来的方案，扔进多场景打分。平台有两套题：一套是可见的，调参的时候随便用；另一套是冻结的——七个场景，不同的起点、不同的地形、不同的噪声，调参的人和 Agent 都碰不到它。（停顿）看结果。刚才自动调优排第一的那套方案，在冻结场景上不及格——达标率只有 57%，跟可见场景的差距 0.158。它不是更好，它只是更适应我们让它看过的题。真正通过验收的，是排在第二的贝叶斯方案：达标率 86%，质量 0.965，稳稳地过。这个差距，平台叫它泛化间隙。如果没有这一步，你会把那套在实验室里最漂亮、在产线上最不稳的方案，交到产线上去。//

这里有一条我们不让步的设计：分数永远是平台确定性算出来的，Agent 只能读证据、下结论，不能碰分数。否则这个循环最后优化的就不是算法，是怎么说服裁判。//

回到硬件。用户要写的东西只有这么多：每个能动的自由度写一个轴，每个要读的指标写一个测量。写完平台自动就知道——这个产品有几个自变量、几个因变量，量程多少，起点在哪。起点是读轴的当前位置来的，因为真实台架没有绝对坐标，只能从现在这个位置开始。// PI 六足，六个自由度，就是六个轴。干涉仪、光功率计，就是测量通道。SFR 计算图特殊一点——它一次拍照，出的是一整张图上很多个视场的 SFR 值。这种情况平台有专门的机制：一次采集，分发给多个因变量。仪器只触发一次，多个指标来自同一次采集——既省时间，物理上也是一致的。而且哪一步不需要哪个通道，就根本不去读它。// 还有一件事，接真机之前客户一定会问：算法跑飞了会不会撞机？平台的安全限位是独立的一层，在评估器里夹紧，关不掉。循环有强制上限，评估次数有预算熔断，条件表达式走白名单。任何算法的 bug、任何 Agent 的失误，都命令不动一次越界运动。//

总结一下。仿真和真机同一个接口，所以算法可以在上机之前做完。变量、目标、设备是声明出来的，所以换产品不用重写，演进产品可以继承。Agent 自动寻优，加上数字孪生多场景验收，所以选出来的方案是最稳最快的那一个，而不是实验室里最好看的那一个。仪器按三个方法接入，所以对接是天级的。// 最后一句：平台的每一个能力都有测试兜着，依赖全部是宽松许可，可以闭源交付。
